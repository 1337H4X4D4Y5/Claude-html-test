Water Box (MPM)

Moving Least Squares Material Point Method fluid, on the GPU via WebGPU compute shaders. Currently a placeholder — the kernels are being built up over several versions.

What MPM is

Particles carry mass + velocity + an affine velocity gradient (3×3 matrix). Each frame, particles scatter their state onto a 3D background grid (P2G), the grid is updated with gravity + boundary conditions, then particles gather new velocities back from the grid (G2P). The grid handles inter-particle pressure implicitly, so there's no spring-pressure crystal lattice — particles can pack to any density and the surface reads as fluid.

Implementation plan

  • Compute shaders: clear grid → P2G (atomic-i32 fixed-point for floats) → grid update → G2P → advect.
  • Grid resolution starts at 32³ ≈ 33k cells; particle count target 30k–60k.
  • Rendering reuses the SSF depth → bilateral blur → composite pipeline from the SPH page.
  • Gyroscope-driven gravity vector wired into the grid-update kernel.

Reference

Following nialltl's MPM guide for the math and matsuoka-601's WebGPU-Ocean for the WebGPU-specific patterns (atomicAdd fixed-point, P2G scatter, MLS gradient reconstruction).

Compare

The current SPH build uses Position-Based Fluids style projection in the compute shader (no spring pressure, so no preferred lattice). Useful baseline while MPM is being built — same gyro input, same SSF rendering, just a different inner physics.
